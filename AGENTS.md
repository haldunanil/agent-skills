# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Cursor, Copilot, etc.) when working with code in this repository.

## Repository Overview

A collection of skills for Claude.ai and Claude Code that automate common development tasks. Skills are packaged instructions and scripts that extend Claude's capabilities.

## Creating a New Skill

### Directory Structure

```
skills/
  {skill-name}/               # kebab-case directory name
    SKILL.md                  # Required: skill definition
    {prompt-file}.md          # Optional: reference prompt files loaded progressively
    scripts/                  # Optional: executable scripts
      {script-name}.sh        # Bash (default), or {script-name}.mjs when the task needs Node
    assets/                   # Optional: static files a script reads at runtime (HTML/CSS/JS templates, etc.)
  {skill-name}.zip            # Generated by the builder for distribution
```

A skill needs a `SKILL.md`. Everything else is optional — use whatever combination of reference prompt files or executable scripts fits the skill's purpose.

### Naming Conventions

- **Skill directory**: `kebab-case` (e.g., `comprehensive-review`, `review-pr-comments`)
- **SKILL.md**: Always uppercase, always this exact filename
- **Scripts**: `kebab-case.sh`, or `kebab-case.mjs` for Node (e.g., `deploy.sh`, `build-walkthrough.mjs`)
- **Zip file**: Must match directory name exactly: `{skill-name}.zip`

### SKILL.md Format

~~~markdown
---

**Examples:**

{Show 2-3 common usage patterns}
~~~

### Best Practices for Context Efficiency

Skills are loaded on-demand — only the skill name and description are loaded at startup. The full `SKILL.md` loads into context only when the agent decides the skill is relevant. To minimize context usage:

- **Keep SKILL.md under 500 lines** — put detailed reference material in separate files (e.g., `action-plan-prompt.md`)
- **Write specific descriptions** — helps the agent know exactly when to activate the skill
- **Use progressive disclosure** — reference supporting files that get read only when needed
- **Prefer scripts over inline code** — script execution doesn't consume context (only output does)
- **File references work one level deep** — link directly from `SKILL.md` to supporting files

### Script Requirements

Bash is the default. Reach for a Node script (`.mjs`) when the task needs it — e.g. robust JSON handling or templating that's fragile in shell. The `pr-walkthrough` skill is the reference example: it ships `scripts/build-walkthrough.mjs` plus an `assets/` directory of HTML/CSS/JS it validates and inlines. Keep Node scripts **stdlib-only** (no npm dependencies) so they run wherever the skill is installed without a `node_modules`.

**Bash scripts:**

- Use `#!/bin/bash` shebang
- Use `set -e` for fail-fast behavior
- Write status messages to stderr: `echo "Message" >&2`
- Write machine-readable output (JSON) to stdout
- Include a cleanup trap for temp files
- Reference the script path as `bash /mnt/skills/user/{skill-name}/scripts/{script}.sh`

**Node scripts:**

- Stdlib only — no npm dependencies, no `node_modules`
- Same stderr/stdout conventions as above
- Reference the script path as `node /mnt/skills/user/{skill-name}/scripts/{script}.mjs`

### Rule-Based Skills (Optional)

For skills that encode many small best-practice rules (each with a title, impact level, explanation, and bad/good code examples), the repo ships a TypeScript build pipeline under `packages/hal-agent-skills/`. It compiles per-rule markdown files from `skills/<name>/rules/` into a generated `AGENTS.md` plus an extractable test-case JSON.

To add a rule-based skill:

1. Create `skills/<name>/rules/` containing one `.md` per rule (frontmatter with `impact`, `section`, `title`) plus a `_sections.md` index.
2. Add `skills/<name>/metadata.json` with `version`, `organization`, `date`, `abstract`.
3. Register the skill in `packages/hal-agent-skills/src/config.ts` by appending to the `SKILLS` map.
4. Run `npm --prefix packages/hal-agent-skills run build-all-rules` to regenerate `AGENTS.md`.

The existing orchestration-style skills (`comprehensive-review`, `review-pr-comments`) do not use this pipeline — they are plain `SKILL.md` + reference prompt files.

### Creating the Zip Package

The builder produces one `{skill-name}.zip` per directory under `skills/`:

```bash
npm --prefix packages/hal-agent-skills run build
```

This runs rule compilation (if any skills are registered) and then zips every `skills/<name>/` into `skills/<name>.zip`. As a manual fallback you can also run `zip -r {skill-name}.zip {skill-name}/` from inside `skills/`.

### End-User Installation

Document these two installation methods for users:

**Claude Code:**

```bash
cp -r skills/{skill-name} ~/.claude/skills/
```

**claude.ai:**
Upload `skills/{skill-name}.zip` to project knowledge, or paste the `SKILL.md` contents into the conversation.

If the skill requires network access, instruct users to add required domains at `claude.ai/settings/capabilities`.
